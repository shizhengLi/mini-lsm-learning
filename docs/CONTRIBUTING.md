# 贡献指南

感谢您对 Mini-LSM 技术博客文档项目的关注！我们欢迎各种形式的贡献，包括文档改进、错误修正、新内容添加等。

## 🎯 如何贡献

### 1. 报告问题
如果您发现文档中的错误或不清楚的地方，请：
- 在 GitHub Issues 中创建新问题
- 详细描述问题所在
- 提供具体的修正建议

### 2. 改进文档
- 修正语法错误和拼写错误
- 添加更多示例和说明
- 改进文档结构和可读性
- 添加更多图表和视觉元素

### 3. 添加新内容
- 新的技术主题
- 更多最佳实践
- 性能优化技巧
- 故障排除指南

### 4. 代码示例
- 改进现有代码示例
- 添加更多使用场景
- 修复代码中的 bug
- 添加性能优化示例

## 📋 贡献流程

### 1. Fork 项目
```bash
# Fork 项目到您的 GitHub 账户
# 然后克隆到本地
git clone https://github.com/your-username/mini-lsm-docs.git
cd mini-lsm-docs
```

### 2. 创建分支
```bash
# 创建新的功能分支
git checkout -b feature/your-feature-name
```

### 3. 进行修改
- 编辑相应的文档文件
- 确保格式正确
- 添加必要的示例和说明

### 4. 提交更改
```bash
# 添加更改到暂存区
git add .

# 提交更改
git commit -m "Add: 添加了新的技术文档章节"
```

### 5. 推送分支
```bash
git push origin feature/your-feature-name
```

### 6. 创建 Pull Request
- 在 GitHub 上创建 Pull Request
- 详细描述您的更改
- 关联相关的问题（如果有）

## 📝 文档规范

### 格式要求
- 使用 Markdown 格式
- 遵循现有文档的风格
- 使用清晰的标题结构
- 适当的代码高亮

### 内容要求
- 技术准确性
- 清晰的示例
- 适当的图表
- 完整的说明

### 代码示例
- 使用 Rust 代码风格
- 包含必要的错误处理
- 添加适当的注释
- 提供完整的使用示例

## 🏷️ Commit 消息规范

### 格式
```
<类型>: <描述>

<详细说明>
```

### 类型
- `Add`: 添加新内容
- `Fix`: 修复错误
- `Update`: 更新内容
- `Docs`: 文档改进
- `Style`: 格式调整
- `Refactor`: 重构内容

### 示例
```
Add: 添加了 Compaction 策略的详细说明

- 详细介绍了三种主要的合并策略
- 添加了性能对比图表
- 提供了代码实现示例
```

## 🧪 质量检查

### 内容检查
- [ ] 技术内容准确无误
- [ ] 代码示例可以正常运行
- [ ] 文档结构清晰合理

### 格式检查
- [ ] Markdown 格式正确
- [ ] 代码块语法高亮正确
- [ ] 链接有效

### 实用性检查
- [ ] 内容对读者有价值

- [ ] 解释清晰易懂
