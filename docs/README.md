## 🔍 核心特性

### 高性能写入
- **内存缓冲**: 通过 MemTable 实现快速写入
- **预写日志**: 保证数据持久性和故障恢复
- **批量合并**: 减少 I/O 操作，提升写入性能

### 高效读取
- **层次化查询**: 从内存到磁盘逐层查询
- **布隆过滤器**: 快速判断键是否存在
- **稀疏索引**: 减少磁盘 I/O 开销

### 智能合并
- **多种策略**: Simple Leveled、Tiered、Leveled Compaction
- **自适应调整**: 根据工作负载动态优化
- **并发控制**: 多线程后台合并，不影响前台性能

### 可靠性保证
- **事务支持**: 基于时间戳的多版本控制
- **故障恢复**: WAL 和检查点机制
- **数据一致性**: 强一致性保证

### 🎯 数据结构专题：跳表核心优势
- **概率平衡**: 使用随机算法避免复杂的旋转操作
- **简洁实现**: 相比平衡树，代码复杂度显著降低
- **天然并发**: 层次结构支持高效的无锁读取
- **性能稳定**: 平均 O(log n) 的时间复杂度，性能可预测
- **内存友好**: 灵活的内存布局和缓存优化策略

## 🛠️ 主要组件

### 1. MemTable
- 跳表 (SkipList) 或 BTreeMap 实现
- 支持前缀压缩和范围查询
- 内存大小监控和自动切换

### 2. SST 文件
- 分层存储结构 (Data Blocks, Index Block, Bloom Filter)
- 前缀压缩编码，减少存储空间
- 支持快速查找和范围扫描

### 3. Compaction 引擎
- 多种合并策略实现
- 智能的文件选择和调度
- 性能监控和自适应调优

### 4. WAL 系统
- 顺序写入优化
- CRC 校验和故障恢复
- 批量写入支持

### 5. MVCC 支持
- 时间戳键编码
- 快照隔离和事务支持
- 垃圾回收和版本管理

## 📈 性能特征

### 写入性能
- **延迟**: 通常在微秒级别
- **吞吐量**: 每秒数万到数十万操作
- **写入放大**: 可配置，通常在 5-20 倍

### 读取性能
- **点查询**: 毫秒级别，缓存命中时更快
- **范围查询**: 取决于数据量和范围大小
- **读取放大**: 1-10 倍，取决于合并策略

### 存储效率
- **空间放大**: 通常在 1.5-3 倍
- **压缩率**: 取决于数据特性
- **碎片整理**: 自动和手动触发

## 🎯 适用场景

### 适合场景
- **写入密集型应用**: 日志系统、时序数据
- **键值存储**: 缓存、会话存储
- **文档数据库**: 基础文档存储
- **分析系统**: 大规模数据分析

### 不适合场景
- **强事务需求**: 需要复杂事务的应用
- **小文件存储**: 大量小文件的直接存储
- **实时分析**: 需要实时聚合分析的场景
- **关系型查询**: 复杂的 SQL 查询

## 🔧 开发指南

### 项目结构
```
mini-lsm/
├── src/
│   ├── lib.rs              # 库入口
│   ├── lsm_storage.rs      # 存储引擎核心
│   ├── mem_table.rs        # 内存表实现
│   ├── table.rs           # SST 表实现
│   ├── block.rs           # 数据块实现
│   ├── compact.rs         # 合并策略
│   ├── wal.rs             # 预写日志
│   └── manifest.rs        # 元数据管理
├── tests/                 # 测试用例
├── benches/               # 性能测试
└── examples/              # 示例代码
```

### 编码规范
- 遵循 Rust 官方编码规范
- 使用 Result<T> 进行错误处理

- 适当的文档注释和示例
